原始程式第 14–95 行。

這是整份程式中比較特殊的部分，因為它不使用 rodio 控制音量，而是直接透過 Windows API 修改作業系統的預設播放裝置音量。

3.1 為什麼要區分兩種音量？

本程式有兩種不同的音量概念：

音量 控制對象 作用
Windows Endpoint Volume Windows 預設播放端點 影響使用該裝置的其他程式
rodio Sink Volume 播放器中的單一音訊串流 只影響本播放器的該個輸出

例如：

假設 Windows 預設喇叭音量是 80%，而播放器中的某個 Sink 音量是 50%。

實際輸出會同時受到兩層音量控制。

因此，兩者不能混為一談。

3.2 #[cfg(windows)]

#[cfg(windows)]
fn get_windows_endpoint_volume() -> anyhow::Result<f32> {

cfg 是 Rust 的條件編譯屬性。

這表示：

只有在 Windows 平台編譯時，才會編譯這個函式。

相反地：

#[cfg(not(windows))]
fn get_windows_endpoint_volume() -> anyhow::Result<f32> {
    anyhow::bail!("Windows 音效端點音量控制僅支援 Windows")
}

表示在非 Windows 平台，使用另一個同名函式。

這種設計的好處是：

  • Windows 可以直接控制系統音量。
  • Linux、macOS 仍然可以編譯其他播放器功能。
  • 不需要在執行期間才判斷作業系統。

這稱為 Conditional Compilation。

3.3 anyhow::Result<f32> 是什麼？

這是 Rust 常見的錯誤回傳型別。

它相當於：

Result<f32, anyhow::Error>

Rust 的 Result 有兩種可能：

Ok(value)
Err(error)

例如：

Ok(0.85)

表示成功讀取音量，數值是 85%。

而：

Err(error)

表示執行過程發生錯誤。

為什麼不直接回傳 f32？

因為 COM 初始化、取得音訊裝置、呼叫 Windows API 都可能失敗。

使用 Result 可以讓呼叫者知道是否成功，而不必用特殊數值表示錯誤。

3.4 unsafe 的用途

unsafe {
    let hr = CoInitializeEx(None, COINIT_MULTITHREADED);
}

Rust 預設會檢查記憶體安全性。

但是 Windows COM API 有一些操作需要呼叫者承擔額外的安全責任，因此部分介面被放在 unsafe 區塊中。

unsafe 並不表示這段程式一定不安全。

它的意思是：

編譯器無法完全證明這些操作符合安全條件，必須由程式設計者負責。

3.5 COM 初始化與 HRESULT

let hr = CoInitializeEx(None, COINIT_MULTITHREADED);

這裡使用 Windows COM 的多執行緒 Apartment 模型。

接著：

let initialized = if hr.0 >= 0 {
    true
} else if hr.0 == 0x8001_0106u32 as i32 {
    false
} else {
    return Err(anyhow::anyhow!(
        "COM 初始化失敗，HRESULT：0x{:08X}",
        hr.0 as u32
    ));
};

這裡有幾個值得學習的語法。

第一：hr.0

hr 是 HRESULT 型別的值，而 .0 表示存取其第一個 tuple 欄位。

第二：as i32

型別轉換。

第三：{:08X}

格式化輸出：

  • X：十六進位大寫。
  • 8：至少八個字元。
  • 0：不足八位時前面補零。

第四：return Err(...)

立即結束函式，回傳錯誤。

3.6 閉包 ||

let result = (|| -> anyhow::Result<f32> {
    let enumerator =
        CoCreateInstance::<_, IMMDeviceEnumerator>(
            &MMDeviceEnumerator,
            None,
            CLSCTX_ALL
        )?;

    let device =
        enumerator.GetDefaultAudioEndpoint(eRender, eMultimedia)?;

    let endpoint: IAudioEndpointVolume =
        device.Activate::<IAudioEndpointVolume>(CLSCTX_ALL, None)?;

    Ok(endpoint.GetMasterVolumeLevelScalar()?.clamp(0.0, 1.0))
})();

這是一個非常值得理解的 Rust 語法。

|| 表示不接受任何參數的閉包。

例如：

let f = || {
    println!("Hello");
};

f();

這裡的寫法：

(|| -> anyhow::Result<f32> {
    // ...
})()

分成兩個動作：

  1. 建立一個閉包。
  2. 立即呼叫這個閉包。

為什麼要這樣設計？

因為閉包內部使用了 ?，可以讓多個 Windows API 錯誤自動傳回 Result。

但是，閉包結束後，外層仍然能執行：

if initialized {
    CoUninitialize();
}

這樣就能確保 COM 的初始化與解除初始化有明確的生命週期。

這是一種將錯誤處理與資源清理分離的設計方式。

3.7 ? 運算子

例如：

let device = enumerator.GetDefaultAudioEndpoint(eRender, eMultimedia)?;

? 的意思是：

  • 如果結果是 Ok(value)，取出 value 繼續執行。
  • 如果結果是 Err(error)，立即回傳錯誤。

相當於：

let device = match enumerator.GetDefaultAudioEndpoint(eRender, eMultimedia) {
    Ok(value) => value,
    Err(error) => return Err(error.into()),
};

? 是 Rust 非常重要的語法，建議熟練掌握。

5.2 Biquad：數位音訊濾波器

#[derive(Clone)]
struct Biquad {
    b0: f32,
    b1: f32,
    b2: f32,
    a1: f32,
    a2: f32,
    z1: f32,
    z2: f32,
}

這是一個二階數位濾波器。

它不是單純調整音量，而是透過數學運算改變特定頻率的響應。

Biquad 是音響 EQ、低通濾波器、高通濾波器及音效處理中非常常見的基本單元。

其數學原理

二階 IIR 濾波器的差分方程式為：

\[ y[n]=b_0x[n]+b_1x[n-1]+b_2x[n-2] -a_1y[n-1]-a_2y[n-2] \]

其中：

  • \(x[n]\)：目前輸入的音訊樣本。
  • \(y[n]\)：目前輸出的音訊樣本。
  • \(b_0,b_1,b_2\)：前饋係數。
  • \(a_1,a_2\)：回授係數。

z1、z2 則是用來保存濾波器過去的運算狀態。

Default 實作

impl Default for Biquad {
    fn default() -> Self {
        Self {
            b0: 1.0,
            b1: 0.0,
            b2: 0.0,
            a1: 0.0,
            a2: 0.0,
            z1: 0.0,
            z2: 0.0,
        }
    }
}

表示為 Biquad 實作 Rust 的 Default Trait。

因此可以使用：

這組初始係數代表：

也就是沒有任何濾波效果，原音直接通過。

q 品質因數，控制頻寬

重要數學運算

let a = 10.0_f32.powf(gain_db / 40.0);

這裡使用浮點數的 powf()，計算：

\[ A=10^{G/40} \]

其中 \(G\) 是增益 dB。

接著：

let w0 = 2.0 * PI * frequency / sample_rate;

換算成數位角頻率：

\[ \omega_0=\frac{2\pi f_0}{f_s} \]

這些公式來自 RBJ Audio EQ Cookbook。

之後程式利用 sin()、cos() 計算濾波器係數。

process()：實際處理音訊

#[inline]
fn process(&mut self, input: f32) -> f32 {
    let output = self.b0 * input + self.z1;

    self.z1 = self.b1 * input - self.a1 * output + self.z2;
    self.z2 = self.b2 * input - self.a2 * output;

    output
}

這裡採用 Transposed Direct Form II。

它的優點是可以用兩個狀態變數保存運算所需的歷史資料。

每次傳入一個音訊樣本，就回傳一個處理後的樣本。

#[inline] 是編譯器提示，希望將函式內嵌到呼叫位置，減少函式呼叫開銷。

不過是否真的內嵌，仍由編譯器決定。

設計上的重要觀念：

濾波器不能每處理一個樣本就重新建立。

因為 z1、z2 必須連續保留，才能產生正確的濾波效果。

所以每個頻道都需要自己的濾波器狀態。

7.2 Arc 是什麼？

這是 Rust 中非常重要的智慧指標。

Arc<PathBuf>

Arc 全名是：

Atomically Reference Counted

意思是原子參照計數。

假設同一個音檔要傳給三個輸出裝置：

                    PathBuf
                       |
                      Arc
                 _____|_____
                |     |     |
              裝置A  裝置B  裝置C

三個裝置可以共享同一個路徑資料。

不用複製三份 PathBuf 的內部字串資料。

Arc 和 Rc 的差別

型別 使用情境
Rc<T> 單執行緒共享
Arc<T> 多執行緒共享

因為音訊輸出可能由不同執行緒處理，因此本程式使用 Arc。

7.3 AtomicBool：播放啟動閘門

start_gate: Arc<AtomicBool>

這是非常巧妙的設計。

假設使用者同時選擇三個音訊輸出裝置。

如果每個裝置建立完成後就立即開始播放，可能會出現：

裝置 A：先播放
裝置 B：晚 20 ms 播放
裝置 C：晚 50 ms 播放

本程式的設計是：

先讓所有裝置建立 Sink，然後才一起開啟播放閘門。

在每個 GatedSource 中：

if !self.start_gate.load(Ordering::Acquire) {
    return Some(0.0);
}

意思是：

如果閘門尚未打開，就持續輸出數值為 0 的音訊樣本。

因此 Sink 可以先建立、預熱，而不會提前消耗真正的音訊內容。

所有裝置準備完成後：

self.start_gate.store(true, Ordering::Release);

這就是共同啟動閘門。

注意：這種方式可以減少各裝置啟動時的時間差，但不代表硬體層級的絕對同步。不同音訊裝置有各自的時鐘與緩衝區，長時間播放仍可能產生時鐘漂移。

7.4 Ordering：原子操作的記憶體順序

程式中有：

Ordering::Relaxed
Ordering::Acquire
Ordering::Release
Ordering::AcqRel

這些不是音訊功能，而是多執行緒記憶體同步機制。

Ordering 意義
Relaxed 只保證原子性，不建立跨變數同步順序
Acquire 確保後續讀取不越過這個讀取操作
Release 確保先前操作不越過這個寫入操作
AcqRel 同時具有 Acquire 和 Release 特性

例如：

以及：

self.start_gate.load(Ordering::Acquire);

配對使用可以建立跨執行緒的同步關係。

這樣音訊執行緒在看到啟動閘門打開時，也能看到啟動前已經發布的相關狀態。

7.9 refresh_eq()：更新 EQ

fn refresh_eq(&mut self) {
    for band in 0..EQ_BANDS {
        let gain = f32::from_bits(
            self.eq_gains[band].load(Ordering::Relaxed)
        );

        if (gain - self.last_gains[band]).abs() > 0.001
            || !self.last_gains[band].is_finite()
        {
            for channel_filters in &mut self.filters {
                channel_filters[band].set_peaking(
                    self.sample_rate as f32,
                    EQ_FREQUENCIES[band],
                    1.0,
                    gain,
                );
            }

            self.last_gains[band] = gain;
        }

}

三、40mm 全音域單體的聲音特性

1. 中頻與人聲表現

40mm 全音域單體的主要優勢在於體積小、單體數量少，而且能以一個振膜重播大部分可聽頻段。

一般適合呈現：

  • 男聲、女聲及語音。
  • 流行音樂中的主唱。
  • 吉他、鋼琴等中頻樂器。
  • 廣播、提示音及影音對白。

單體不需要額外分音器來分配高音與中音，因此在適當的箱體和安裝條件下，可以減少多單體之間的相位與銜接問題。

但要注意，全音域不代表所有頻率都能以相同音量、相同失真表現重播。

2. 低頻表現

40mm 單體最大的物理限制就是振膜面積。

以40RR為例：

  • 共振頻率為150Hz ±30Hz。
  • 代表單體本身的機械與聲學共振特性集中在這個區域。
  • 不代表150Hz以下完全沒有聲音。
  • 但不能期待它像3吋、4吋或更大型單體一樣，提供充足的低頻能量。

實際低頻表現還會受到以下因素影響：

  • 箱體容積。
  • 密閉式或低音反射式設計。
  • 箱體氣密程度。
  • 振膜衝程。
  • 單體安裝方式。

因此，40mm 單體較適合以中頻、人聲清晰度及小型化為主要設計目標。

3. 高頻表現

40RR 官方標示的有效頻率響應為 Fo～20kHz，最大偏差 -10dB。

此為規格書上的頻率響應範圍，不代表20kHz仍然有平坦的輸出。

實際高頻表現還需要觀察頻率響應曲線，特別是：

  • 5kHz～10kHz 是否有明顯峰谷。
  • 10kHz以上的衰減情形。
  • 振膜分割振動造成的響應起伏。
  • 不同聆聽角度的高頻變化。

對小型全音域單體而言，這些因素會直接影響聲音是否明亮、刺耳或有細節。

• 箱體內部用隔板將左、右兩顆喇叭徹底隔開。 • 單顆建議內淨容積：約 0.25 ～ 0.4 公升（250cc ～ 400cc）（例如單邊內部尺寸約 7cm × 7cm × 7cm），能讓 40mm 單體發揮最飽滿的中低頻，不至於過度壓抑振膜或失去控制力。

• 氣密處理：喇叭單體與面板之間加一圈 1mm～2mm EVA 泡棉墊片，板材接縫處用白膠或熱熔膠封死，避免漏氣產生風切雜音。

• 吸音棉：在每個音腔內塞入少量蓬鬆的聚酯纖維吸音棉（約佔容積的 30%～50%，不要壓實），可減少箱內駐波、讓中音更乾淨。

• 獨立電路倉（Rear Electronics Compartment）：

• 將擴音卡、電池與開關放在後方或下方的獨立隔間，與喇叭音腔完全隔離。

• 好處：避免音腔內氣壓震動導致接線鬆脫或產生電容微音雜訊，也方便日後拆背板維修。

二、 外觀尺寸與開孔規劃建議

以桌面型一體式立體聲藍牙喇叭為例，整體外觀尺寸建議落在 寬 18cm × 高 8.5cm × 深 9cm 左右（視覺比例協調且便於擺放）：

前障板（Front Baffle）開孔：

• 單體開孔：音瀚 4040S-AS 為 40mm 正方形外框，開孔直徑約 36mm～38mm（依實際單體盆架內徑微調，預留 0.5mm 公差），四個角落對應螺絲孔鎖緊。

• 倒角處理：若板材較厚（如 9mm），建議在開孔內側做 45 度倒角或擴孔，避免深孔道形成「筒音」遮擋中高頻擴散。

• 微仰角設計：前障板或箱體底部可設計 5°～10° 微仰角，讓聲音直接指向坐姿時的耳朵高度，近場聆聽的結像感會好很多。

背板（Rear Panel）開孔：

• 電源充電孔：對應擴音卡的 Micro USB 或 Type-C 孔位精準開孔，若卡板位置較深，建議改用面板安裝式延長線拉到背板，插拔更耐用。

• 實體電源開關：強烈建議在電池／電源正極串接一個船型開關或撥動開關鎖在背板，不使用時可徹底斷電（解決部分擴音卡待機微耗電問題）。

• 指示燈導光：在擴音卡的藍牙狀態 LED 正後方鑽一個 2mm～3mm 小孔，塞入一小段透明壓克力棒或熱熔膠柱作為導光柱，不需看背板也能確認連線狀態。

三、 內部佈線與抗干擾細節

• PCB 藍牙天線避開遮蔽：擴音卡上的蛇形走線（天線端）絕對不要緊貼喇叭背後的磁鐵，也不要放在金屬電池（如 18650）正後方；天線端應朝向木質或塑膠外殼邊緣，並保持至少 2cm 以上距離。

• 穿線孔密封：喇叭線從「電路倉」穿入「左右音腔」時，穿線孔務必用熱熔膠或矽利康封死，維持音腔氣密。

• 電池固定：若內建 18650 鋰電池，建議使用專用電池盒或用雙面泡棉膠＋束線帶固定在底板，避免重低音震動時電池撞擊外殼發出異音。

• 底部減震腳墊：箱體底部四角貼上 矽膠止滑墊（高度 2mm～3mm），可防止低頻震動傳導到桌面產生嗡嗡共振聲。 如果你想進一步微調設計圖或機構細節，可以告訴我：

• 預計使用的外殼材料與製作方式（雷射切割木板、3D 列印、手工鋸木或現成盒改造）

• 外型偏好（桌面一體式長條音箱、還是左右分離式小對箱）

• 是否需要加入被動輻射器（低音震膜） 來強化 40mm 單體的低頻下潛

立方體設計配置考量

將兩個 40mm 單體裝在立方體（Cube）的兩個相鄰側面，並讓立方體的「稜線（轉角）」正對自己（兩顆喇叭各向左右偏轉 45°），這種幾何結構在聲學上屬於「雙向擴散／偶極反射（Bipolar / Angled Dispersion）」配置。

這個造型非常適合桌面近場擺放，因為能創造出比一般平面小音箱更寬廣的音場；但因為兩顆單體夾角達 90° 且3D 列印塑膠殼較輕薄，需要針對相位干擾、箱體共振、低頻量感與擺位反射做以下四項關鍵優化，才能達到最佳音響效果：

一、 聲學核心：利用「90° 夾角」創造寬廣音場，同時避免梳狀濾波

當立方體的稜線朝向你（兩面各 45° 向外發聲）時，聲音會往左前方與右前方擴散：

單體盡量靠近「正中央的稜線」安裝：

• 在兩個相鄰的面上，不要把喇叭開孔放在面的正中心，而是稍微往兩面交界的「前稜線」靠攏（邊緣距離稜線約 8mm～12mm 即可）。

• 聲學原因：縮短兩顆單體振膜之間的物理距離，能減少高頻聲波在正前方交會時的時間差與相位抵消（梳狀濾波效應），讓人聲（中頻結像）穩穩凝聚在稜線正前方，不會覺得聲音散開或空洞。

擺位距離牆面 15cm～25cm：

• 由於兩顆單體朝左右 45° 斜後方反射，桌面後方或側邊若有牆面，聲波經牆面反射後會形成自然的環繞包圍感；但若貼牆太近（< 5cm）會導致低頻混濁，建議距離後牆約 15cm～25cm 效果最佳。

加入 5°～8° 仰角底座： • Cube 放在桌面上高度較低，建議在列印件底部一體成型設計一個 5°～8° 的微仰角底座（讓朝向你的那條底邊稍微墊高），使 45° 斜向發聲的軸線直接對準耳朵高度，高頻細節會清晰很多。

二、 3D 列印箱體結構：克服「塑膠殼共振與單薄感」

3D 列印件（PLA / PETG）的密度與內阻尼遠低於木頭，若直接列印薄殼，開大聲時外殼會跟著震動發出「塑膠共鳴聲」。建議在建模與切片時做以下處理：

壁厚與內部補強肋（Ribs）：

• 外壁厚度：建議設定為 3.5mm ～ 4.5mm（或 4～5 層外牆 Perimeters ＋ 30%～40% 螺旋體 Gyroid 填充），能有效壓制中頻箱體共振。

• 交叉加強肋：在兩個喇叭背後的音腔內壁，印出高度約 3mm～4mm 的十字形加強肋條，大幅提升平面抗形變能力。

推薦使用「單一被動輻射器（低音震膜）」補齊低頻：

• 音瀚 40mm 單體的共振頻率為 150Hz，在小型立方體內若純做密閉箱，低頻下潛有限。

• 建議在立方體的其中一個背面或頂面，加裝一片 40mm～50mm 的被動輻射器（Passive Radiator，無磁鐵的橡膠震膜），與兩顆單體共用一個經過計算的獨立音腔（約 350cc～450cc）。這樣不需開倒相孔（避免小箱體風切聲），就能讓低頻下潛延伸至 80Hz～90Hz 左右，聽感會渾厚非常多。

• 註：若不加被動輻射器，則維持「左右各自獨立密閉音腔（各約 200cc～250cc）」最保險，低頻較緊實不鬆散。

材質選擇建議：

• PETG 或 霧面 PLA（Matte PLA） 優於一般亮面 PLA：PETG 韌性較好、內阻尼稍高，較不容易產生高頻脆響；若使用木質纖維 PLA（Wood PLA）並把壁厚印到 4mm，聲學阻尼表現會更接近密集板。

三、 立方體內部空間配置（建議尺寸：10cm × 10cm × 10cm）

以 100mm × 100mm × 100mm 的立方體為例，扣除 4mm 壁厚後內部淨空間約為 92mm × 92mm × 92mm（約 778cc），非常適合做「前上聲學區 ＋ 後下電路倉」的斜向隔板分艙：

• 前側 V 型音腔（兩顆單體所在區域）：

• 兩顆 40mm 單體分別裝在「左前面」與「右前面」，單體背後的磁鐵在立方體內部會呈現 90° 交錯，設計時務必確認兩顆磁鐵後方在中心交會處不會互相碰撞（10cm 立方體空間足夠錯開）。

• 音腔內部貼一層 2mm 自黏式吸音棉或汽車隔音止震墊（丁基橡膠），能瞬間消除 3D 列印塑膠壁的空洞回音，這對 3D 列印音箱的音質提升最明顯。

• 後下三角電路倉（兩背面交界處）：

• 利用一塊斜向隔板（或列印一體成型的隔離艙壁），將「左背面」與「右背面」交界的後方角落隔出一個獨立三角形空間，用來放 5W 藍牙擴音卡、18650 電池、開關與充電孔。 • 藍牙天線位置：把擴音卡的 PCB 藍牙天線貼近「後背板」內側，遠離前方兩顆喇叭的磁鐵，訊號完全不會被遮擋。

四、 組裝氣密與減震細節

列印件接縫氣密：立方體建議拆成「主箱體」＋「後方維修底蓋／背蓋」兩件式列印。蓋子接合處設計 凹凸止口（榫槽），組裝時在溝槽內塗一圈 矽利康（Silicone） 或夾入 1.5mm TPU 軟料列印墊圈，確保音腔完全不漏氣。

螺絲固定優先於膠黏：開孔處預留 M3 熱熔螺母（Heat-set Inserts） 孔位，用螺絲把單體與背蓋鎖緊，並在單體邊框貼一圈 EVA 泡棉膠帶，既氣密又方便日後拆裝調音。

TPU 軟料減震腳墊：若有多色／多材質列印機，或另印四顆 TPU 95A 軟料腳墊 黏在底部四角，可徹底阻絕立方體把震動傳導到桌面上。 如果你想進一步精算結構尺寸，可以告訴我：
